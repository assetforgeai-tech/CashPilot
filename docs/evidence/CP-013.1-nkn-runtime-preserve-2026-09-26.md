# CP-013.1 NKN helper runtime-directory preservation

## Scope

- Code-only regression fix for the NKN host-helper systemd unit.
- No Azure, SSH, production, provider, wallet, lease, or worker mutation.
- NKN deployment was not retried.

## Corrected root cause

The earlier CP-013 Stage 1 note said the worker compose omitted the NKN socket
mount. That conclusion is superseded. Read-only `docker inspect` showed the
effective worker container has the bind mount
`/run/cashpilot-nkn-agent:/run/cashpilot-nkn-agent`.

The failure occurred after the helper restarted. At the captured timeline, the
worker started at `04:17 UTC`, the NKN helper restarted at `06:58 UTC`, and the
host runtime directory inode was `140377` while the directory visible through
the existing container mount was inode `1633`. The host had `agent.sock`; the
container did not. `RuntimeDirectory=` allowed systemd to replace the host
runtime directory on service restart, leaving the long-lived worker attached to
the old directory inode.

The minimal fix is `RuntimeDirectoryPreserve=yes` in
`scripts/cashpilot-nkn-agent.service`, matching the already-protected
EarnApp helper unit. This preserves the runtime directory across helper
restarts so the bind mount remains valid.
