## Live canary result

Overall result: **FAIL; rollout stopped**. The canary produced useful positive
network evidence, then exposed two operational defects. No production rollout
was attempted.

- East Asia recovery: the first read-only Run Command left the VM Agent
  unresponsive. A normal restart remained stuck. Deallocate/start recovered the
  same VM and all static public IP mappings; worker and provider containers
  returned.
- Disposable runtime: Ubuntu node
  `earnapp-disposable-w118904-rotation-04` deployed through the normal API on
  worker `118904`. Provider verification remained `pending` because the account
  operation queue did not complete during this bounded run.
- Egress: repeated HTTPS egress returned the assigned proxy IP. The host packet
  capture showed the canary talking to the proxy endpoint; no direct target
  connection was observed.
- DNS/IPv6: the container used local resolver `127.0.0.1`; IPv6 had a terminal
  DROP chain and the IPv6 HTTPS probe failed closed. DNS used the local proxy
  path, but a separate DoH signature capture was not completed, so `dns_doh`
  remains `INCONCLUSIVE`.
- UDP: non-DNS traffic had no allow rule and a terminal DROP existed. The run
  did not capture a distinct UDP packet/counter increment, so `udp` remains
  `INCONCLUSIVE` rather than inferred PASS.
- Watchdog/rotation: the guarded endpoint accepted exactly three unhealthy
  samples and reported `direct_fallback_blocked=true`, but returned
  `rotation_requested=false`. Gate `watchdog` is `FAIL`; the runtime was not
  silently rotated.
- Reboot: Japan East returned healthy, but systemd selected
  `ghcr.io/assetforgeai-tech/cashpilot-worker:proxybase-fix-20260921` instead of
  the pre-reboot `cashpilot-phase7-worker:20260921`. This proves worker image
  persistence drift. Gate `reboot` is `FAIL`.
- Cleanup: the disposable container was removed, the canary binding rolled
  back, and the logical node returned to `PLANNED` with no assigned worker,
  device, or proxy. Japan East was returned to the image pinned by its systemd
  unit; both worker services are healthy.
