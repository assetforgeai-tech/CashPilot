# CP-014C evidence — atomic worker-resource reclamation

## Scope

Implemented `database.reclaim_worker_resources()` as one SQLite `BEGIN IMMEDIATE`
transaction. It releases active proxy leases, NKN/Myst wallet leases, retires
provider runtime assignments, and increments the worker resource generation.
Credentials, provider/account identity, sticky egress ownership, wallet
identity, and history remain untouched.

## Safety properties

- `reclamation_token` is durable and idempotent; replay returns the original
  generation without mutating rows again.
- `resource_generation` increments on successful reclamation and can be checked
  by later scheduler/heartbeat work to fence the old worker generation.
- `expected_generation` rejects stale reclamation attempts.
- Missing token, unknown worker, and generation mismatch fail closed.
- No Azure, VPS, provider, or production mutation performed.
